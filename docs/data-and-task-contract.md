# 数据、任务与预算合同

2026-11-21 源码批次；远程集成尚未执行。当前接口前缀 `/api/v1`。

## 数据合同

`POST /datasets` 接收 `{scenario,name,format,content}`，其中 format 为 `csv` 或 `json`，content 为文件文本。最多 10 MB、20,000 行；反向代理请求体上限 12 MiB。CSV 和 JSON 对象使用相同字段：

```text
date,channel,region,category,segment,visitors,orders,revenue,material,logistics,commission,other,tax,spend
```

日期、渠道、区域、品类、客群组成唯一业务键。数值必须有限且非负，访问及订单为整数；访问次数不等于去重 UV。金额为元，JSON 小数直接按十进制文本解析。日期连续，每个日期包含同一组业务组合；停业、缺货或新增业务需提供明确的零记录，系统不会自动补成已观测零值。

版本仅本人在仍获授权的业务线内可见，没有修改接口；重新导入得到新版本，同一人同一业务线相同内容返回既有版本。内容与排序规范化后计算 SHA-256，当前不会合并只有小数书写精度不同的文件。合成数据显式标记，不能用于证明真实经营原因。

`POST /datasets/demo` 生成指定业务线的 90 天合成日聚合版本；`GET /datasets` 列出本人的最新 100 个版本。

`POST /sessions` 可附带 dataset_id 和 scope；scope 必须包含 baseline/current 两个日期对、filters 字典与 group_by。日期 YYYY-MM-DD，两期等长、不重叠、覆盖完整。未提供 scope 默认最新两段 30 天；不足 60 天的数据须手动选择日期。固定 PRD 汇总样例仍支持原有创建方式，不能多轮筛选。

## 任务合同

`POST /sessions/{id}/runs` 接收 question、request_key、mode（rules/deepseek），成功返回 202 和任务记录。一次用户提交固定一个幂等键，网络错误重试必须复用；编辑问题或明确发起重试使用新键。同键不同请求返回 409。相同会话同时只有一个 queued/running 任务。

状态流：queued → running → succeeded / needs_input / failed / cancelled。当前 succeeded 只表示数学分析完成，不表示统计检验完成。

worker 使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取任务，每次生成新的 fence，租约 60 秒、每 10 秒续约，进程中断后最多领取 3 次。续约或提交时须匹配当前 fence、有效租约、running 状态和当前权限。旧 worker、取消任务或撤权后的结果不能更新会话快照。正常业务错误直接终结；新提交可重试。

`POST /runs/{id}/cancel` 取消活动任务，终结状态下幂等返回。已经进入供应商调用的费用仍计入账本；取消不会自动释放未知用量预留。

`GET /sessions/{id}/runs` 恢复最近 100 次任务记录；`GET /runs/{id}` 读取状态及该任务冻结结果。`GET /runs/{id}/events?after=N` 支持 Last-Event-ID 增量回放，progress 事件包含单调序号，done 事件结束当前流。连接约 110 秒自动重连，每批读取重新检查登录、账号状态、业务权限及所有权；不跨等待持有数据库事务。

规则模式只支持明确维度值、按渠道/区域/品类/客群分组、清除筛选、返回全国和返回上一级。无法解析的剩余条件会要求明确问题，不会静默忽略否定、日期或预测条件。最多保存 50 层范围回退。

DeepSeek 接收问题、上一轮范围和当前数据版本的维度字典，不接收明细行、数据库凭据或 API Key 内容。返回范围必须再次通过与规则模式相同的服务端校验。模型结果不能更换业务线、数据版本或权限；不执行模型生成的 SQL/Python。

## 累计预算

迁移创建 development 账本，累计上限 25 元。每次网络请求之前，锁定账本并按 UTF-8 输入长度上界、协议余量、2048 输出 token 上限预留。无额外模型自动重试；worker 重新领取产生的新模型请求也必须重新预留。

供应商返回可靠 token 用量后，按配置的最高费率保守结算；缓存优惠未扣除，账本不是精确财务账单。请求超时、网络结果不明或缺失用量保留预留，标为 usage_unknown；保存调用模型、核价日期、费率和供应商 usage，供远程核对。未实现自动对账或人工调整界面。

预算不足、价格无效、未核价/核价过期、Key 缺失均在发起请求前拒绝。源代码同时强制 25 元上限，不能仅改环境变量提高。若用户批准追加，须记录批准金额后再更新约束与账本；当前没有追加授权。

管理员可在页面或 `GET /admin/budget` 查看已结算估算、预留、余额。任务错误详情不会回显密钥或供应商原始错误响应。API 进程不接收 DeepSeek Key；只有 worker 接收。

## 远程验收顺序

1. 备份第一阶段数据库，构建依赖，迁移到 0002；在隔离测试数据库运行 integration 测试，不得对业务数据库运行测试套件。
2. 启动 API、worker 与前端；生成两场景数据并检查日期、下钻总和、实际快照模拟和导出范围。
3. 重复提交相同幂等键、提交不同内容、并发追问、取消、关闭 worker 后恢复、撤销权限和 SSE 断线重连。
4. 用模拟供应商验证预算不足、调用成功结算、结果不明保留预留；确认后仅使用有限真实 DeepSeek 请求，计入同一账本。
5. 执行前端编译与浏览器验收。随后再接入独立 gVisor 统计沙箱、事件检索和报告模块；不得用普通本机进程冒充沙箱。
