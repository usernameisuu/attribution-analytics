## 2 目标与范围决定

### 2.1 本轮设计的默认决定

1. 首版面向单企业、多业务线、多指标域，不引入 SaaS 租户计费体系。
2. 首批完整场景为电商 GMV 与快消品毛利率、净利率；保留 PRD 全部 P0/P1 范围。
3. Windows 保留代码编辑与轻量检查；用户明确要求不在本机搭建运行环境，并确认已有 Docker 位于本机，顾虑是显存与磁盘空间。依赖安装、镜像构建、数据库持久卷及沙箱运行安排在远程环境，本机不新建 Linux/虚拟机或容器测试环境，不下载模型权重。不把缺少沙箱的模式当作完整交付。
4. 先支持版本化 CSV/JSON 数据导入和内置模拟数据。外部业务数据库连接器以接口边界保留，具体系统接入不在当前首版清单中。
5. 本地账号认证、服务端会话及角色/数据范围授权先落地；不预设企业 SSO。
6. 模型提供商通过后端适配器配置；先实现兼容的结构化 HTTP 调用接口及明确标识的规则模式。不将没有有效凭据的模型测试记为通过。
7. 报告采用版本、批注和冲突检测协作；简报在站内交付，自动简报标记未经人工复核，正式报告审核后发布。

以上默认决定已随用户对本文的批准确认为首版范围；后续变更以 PRD 和设计变更记录追踪，不重复询问已批准事项。

### 2.2 非目标与必须避免的结果

首版不执行真实调价、资金或预算调整，不实现通用代码托管服务、任意插件安装、多人实时正文编辑、任意外部连接器、Kubernetes 集群和跨地域高可用。

不可接受：固定图表冒充分析、模板回复冒充模型、未执行检验却显示成功、把相关性视为因果、用普通子进程冒充隔离沙箱、跨业务线泄漏、已发布报告被新数据覆盖、重复任务产生重复业务结果。

| 模块 | 拥有的数据和职责 | 禁止跨越的边界 |

## 5 身份、权限和可见性

- 本地账号使用强口令散列；登录建立服务端会话。浏览器使用 HttpOnly、SameSite Cookie，生产启用 Secure。写请求校验 CSRF/Origin，登录实施速率限制。
- 账号状态、角色和 `permission_revision` 存储在数据库，退出及停用使会话失效。认证、授权、资源所有权分别校验。
- 每个业务对象持有 `business_line_id`，必要时持有 `metric_domain_id`；权限由角色能力与数据范围取交集。
- 分析会话默认仅创建者可读写。报告通过明确的读者 ACL 共享；读者必须同时拥有该报告完整数据范围。无完整范围则拒绝访问，不对冻结报告静默删行。
- 事件流、下载、历史案例、重试和定时任务复用同一授权服务。权限变更后禁止新子任务和结果交付，取消运行中的受限任务；SSE 每次重连及发送前检查权限修订。
- 服务端响应携带权限修订号；活动页面发现变更后清理业务缓存。已经合法下载的离线文件无法被远程撤回，系统不承诺该能力。
- PostgreSQL 使用应用层过滤加 RLS，迁移账号与运行账号分离。运行账号不拥有表、不持有 BYPASSRLS；作用域在事务内由可信服务设置，连接回池前清理。

RLS 需要专门验收表拥有者和特权绕过路径；不能把启用策略等同于所有角色均受限制。参见 [PostgreSQL 行级安全文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)。

## 6 数据模型、导入和版本

### 6.1 核心实体及约束

| 实体组 | 主要实体 | 关键约束 |
| --- | --- | --- |
| 权限 | users、auth_sessions、roles、grants、report_acl | 会话令牌只保存摘要；业务访问必须同时满足能力与范围 |
| 元数据 | business_lines、domains、metrics、metric_versions | 指标编码域内唯一；已发布版本不可变；禁止循环引用 |
| 数据 | datasets、dataset_versions、import_batches、facts、dimensions | 版本内业务键唯一；导入通过后一次性发布 |
| 经营目标 | target_plans、target_versions、target_values | 固定适用周期、指标、业务范围、单位和目标因子；已发布版本不可变 |
| 分析 | sessions、scope_versions、runs、steps、hypotheses、evidence | 会话同时一个活动写任务；范围及算法版本不可变 |
| 调度 | jobs、job_attempts、run_events、leases | 幂等键唯一；租约代数递增；事件在任务内单调编号 |
| 业务上下文 | business_events、history_index | 时间、范围和来源可追踪；历史索引引用已发布报告版本 |
| 输出 | scenarios、actions、reports、report_versions、comments、artifacts | 导出按报告版本与格式唯一；编辑采用乐观锁 |
| 运维 | subscriptions、subscription_runs、audit_events | 订阅周期去重；审计应用账号只能追加 |

金额源字段使用十进制定点数，日期与时间戳分开建模。标识采用不承载业务含义的 ID。JSON 字段用于结构化计划、公式树和快照，不替代核心关联约束。

### 6.2 导入与数据版本

1. 文件进入暂存区，限制文件大小、允许格式和行数，不执行上传内容。
2. 校验字段类型、币种、主键、日期、空值、负值业务含义、维度引用及聚合一致性，输出行级错误。
3. 将有效批次写为新版本，事务提交后更新当前版本指针；失败不覆盖旧版本。
4. 分析开始时固定 `dataset_version_id`、`metric_version_id`、`algorithm_version`、范围和参数摘要。
5. 导入更新只影响新分析；已发布报告持有冻结结果、图表数据和证据引用。

首版仅对已经规范化的示例域开放 CSV/JSON 字段映射，其他模型显示不支持而非强行映射。生产数据连接器的增量同步、水位和企业凭据留待实际来源确定。

目标值通过管理页面或相同校验流程的 CSV/JSON 导入，保存指标、适用周期、业务线、维度范围、单位、目标版本及可选的因子目标。目标差分析绑定目标版本：只有总目标时只展示实际与目标差额，并说明无法进行目标因子分解；全部所需因子目标齐备且复合公式与总目标一致时，才以目标因子作为比较端分解。缺失目标时拒绝目标差分析，不用上期实际值或实际因子冒充目标。目标未指定的更细维度不自动均摊。

### 6.3 明细粒度

电商订单按订单行保存，订单数按订单 ID 去重；访问明细保留脱敏 visitor_id、事件时间和维度。周期 UV 对筛选范围内 visitor_id 去重，不能累加每日 UV。日期聚合表仅用于可加总数量或已说明的单日 UV，任意周期 UV 从明细或等价可合并去重集合计算。

一笔订单涉及多个商品品类时，金额按订单行分配，整单优惠按行金额比例分摊并保留可复核舍入调整；各品类金额之和等于整单金额。各品类的去重订单数可以重叠，因此显示“不可跨品类相加”，总订单数另从完整范围去重；不得用品类订单数之和计算整体客单价。订单行与访问明细先各自按最终查询粒度聚合，再连接，禁止直接原始多对多连接造成金额膨胀。

需要可加总的转化率维度贡献时，使用明确命名的“访客归属维度”：按所选比较期内每位访客首次有效访问及确定性事件 ID 破除同时间并列，将访客及其关联订单分配到同一互斥渠道/区域桶；两期分别应用同一规则。该视角不冒充按成交商品分组的品类视角。商品品类透视保留真实可重叠的去重计数，仅对可加总金额做差额贡献。没有跨日或跨切片去重依据的数据源不提供 UV 指标，只提供明确命名的访问次数等可计算指标。

GMV 来源固定为样例有效订单金额；退款、税费和时间口径写入指标版本。客单价为 GMV/有效订单数。人均多单时使用订单数/访客数作为明确命名的转化因子，或增加人均订单数因子，不套用购买人数转化率。

历史仿真所需的渠道投放表额外保存日期、渠道、投入金额、曝光/访问量、活动标识和已知控制变量，与流量按相同粒度关联。模拟数据提供独立于日历趋势的投入变化，保留生成参数；缺少投入字段时禁用预算弹性估计，不能从 GMV 凭空反推投入。

快消品按日期、业务维度和成本类型存储可加总事实，成本分摊规则随版本保存。毛利、经营利润和净利润分别建模；税费零值是显式数据，不能用缺失值代替。

## 7 指标模型与贡献计算

### 7.1 公式

公式使用受限表达式树：指标引用、常量、加减乘除和显式聚合；不使用 eval。保存前检查引用、单位、树深度、节点数及除零条件。比率必须先聚合分子分母，再计算比值。

每一层树展示该节点自身单位的基期、现期与子项贡献；子层金额、人数和比例不伪装成同一根指标的贡献。切换节点时瀑布图标题和单位同步变化，不能混合层级求和。

### 7.2 分解策略

| 输入 | 算法与行为 |
| --- | --- |
| 加法或减法 | 每个因子的差额乘以公式系数，结果严格相加 |
| 正值乘法 | LMDI；对数平均在相等及相近值处采用稳定数值实现 |
| 零值或负值乘法 | 因子数不超过 8 时改用精确 Shapley，并明示替代原因；不偷偷添加小正数 |
| 比率及受限混合公式 | 在不超过 8 个独立驱动因子上采用精确 Shapley；检查所有反事实组合的分母及合法性 |
| 不能合法求值或过多因子 | 拒绝当前拆解并提示改用已定义层级；不返回未声明的近似值 |
| 渠道等维度金额贡献 | 对互斥切片使用现期与基期差额；新增、消失切片以业务上确定的零补齐，缺数不能补零 |
| 比率维度解释 | 可加总且互斥的切片采用分子/分母双因素 Shapley 再按切片差额分摊，不受 8 因子上限限制；可重叠计数先转为明确的互斥归属视角或只展示计数与限制 |

正值乘法 `Y = ∏xᵢ` 的贡献定义为 `L(Y₁,Y₀) × ln(xᵢ₁/xᵢ₀)`，其中 `L(a,b) = (a−b)/(ln(a)−ln(b))`，`a=b` 时使用连续极限 `L(a,a)=a`。所有因子使用同一指标口径，贡献总和对应 `Y₁−Y₀`。

Shapley 对同一函数使用基期/现期替换计算，独立因子不同时包含某个原子指标及其派生值，避免重复计量；结果记录因子集合、公式及算法版本。

对于整体比率 `R=N/D`，两期总分母均大于零、切片分子分母均可加总时，第 i 个切片的比例贡献定义为 `cᵢ = 0.5×(1/D₀+1/D₁)×ΔNᵢ − (N₀+N₁)/(2×D₀×D₁)×ΔDᵢ`。先对总分子和总分母作两因素 Shapley，再用其线性差额分摊至切片，满足 `Σcᵢ=R₁−R₀`。这是明示的层级分摊规则，不声称等同于把所有切片同时作为独立玩家的 Shapley 值。以百分点展示时乘以 100，渠道×区域等 12 个及更多组合按同一公式计算；零或非法总分母返回不可计算。

贡献率在总变化接近零时返回空值及原因；允许负贡献率和超过 100%。金额按内部精度计算，显示误差不超过 0.01 元；比例内部误差建议不超过 1e−10。舍入调整若展示必须单列且仅用于显示，不修饰算法残差。

## 8 假设、检验与事件解释

### 8.1 计划和证据合同

模型只能返回经过结构校验的意图、范围补丁、3～5 条候选假设和证据解释。假设包含类型、目标变量、对照范围、预期方向、数据需求和预定义检验候选，不允许自定权限、运行镜像或数据库对象。

由当前异常数据生成的初轮假设及后续追问统一标记为探索性分析。执行前冻结本轮假设集合和检验计划，禁止根据检验结果改写同一计划；冻结和多重比较调整不能消除已经看过数据再选择假设的偏差，不把这类结果宣称为确认性检验。

若需要确认性验证，必须有在接触验证数据前登记的假设、指标、方法和阈值，以及独立的新数据或未用于选题的留出数据；使用者已经看过的全量大盘不能被重新命名为独立留出。首版默认交付探索性证据，不强制宣称具备确认性因果结论。证据保存分析性质、数据划分/登记依据、代码摘要、输入哈希、执行记录、样本量、效应量、适用检验量、原始及调整 p 值、区间和限制。

### 8.2 统计默认

- 首版支持二元比例比较、连续量均值比较、相关分析和分层对照；具体方法由变量类型和样本假设确定，不由模型凭空指定结果。
- 独立样本连续量可使用 Welch 比较；二元事件按独立观测检验。重复客户或日序列用客户/日期作为统计单位，不能把聚合行当成独立用户样本。
- 每个检验计划明确最小可检测效应、样本充分性规则和所需数据类型。缺失独立性依据或样本充分性依据时返回证据不足。
- 同一冻结假设集合默认采用 Benjamini–Yekutieli 调整，阈值 0.05，保留原始 p 值；该方法允许有效 p 值之间存在依赖，但不修复数据驱动选题带来的选择偏差。探索性结果展示调整方式及限制，不承诺整个自动寻因过程的错误发现率已受控。参见 [SciPy 多重检验调整说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html)。
- 支持状态需满足方向一致、达到冻结的业务效应阈值和统计门槛，并同时展示“探索性”或满足独立验证条件的分析性质。样本充分而未达支持标准时展示 PRD 的“已排除”，说明仅限本次证据；不足和失败为独立状态。
- 不把 1−p 或模型自评命名为原因成立概率。区间显示区间类型和水平，不用未经定义的统一“置信分”。

方法参数的具体值写入版本化场景检验配置，并在实现前通过固定案例和反例验证。精确样本量与效应阈值属于分析配置，不宣称存在适用于所有企业的默认统计标准。

### 8.3 业务事件与历史归因

按分析窗口两端各扩展 3 个自然日，匹配有时间交集的事件，再核对业务线、品类、渠道、区域及方向；保存匹配原因，不把相关评分当作因果概率。

历史案例只索引已发布报告，按授权范围、指标和异常类型检索，显示旧数据与当前数据差异。旧结论只产生候选假设，必须用当前快照重新验证。

结论分级为事实变化、统计关联和有识别假设支持的因果解释。首版事件默认归入统计关联或待验证解释；不承诺识别所有异动的唯一真实原因。

## 9 数据沙箱

### 9.1 数据流与执行权限

可信 worker 通过授权查询器导出本任务最小所需的数据切片。runner 只接收不可变切片、代码、任务身份和服务端生成的资源配置；不接收数据库密码、模型密钥或用户可控主机挂载路径。

SQL 在沙箱内的只读 SQLite 切片库执行：禁止 ATTACH、写操作、扩展加载和未经允许的 PRAGMA/函数；允许对象来自切片清单。设置只读连接、authorizer 和查询步数/时间上限。Python 仅读取该切片及固定运行库，写入受限临时区；不在 API 或 worker 宿主直接运行动态代码。

动态 Python 限定为数据分析子集：显式允许的赋值、分支、有限迭代、聚合和统计库调用；导入仅限固定分析库，禁止动态导入、反射、双下划线访问、外部进程和自定义原生扩展。拒绝不在能力集合内的代码，而非只匹配危险字符串。合法代码执行使用固定入口、固定运行镜像和 gVisor。检查器不是安全隔离边界，必须有运行时隔离和越界测试。

### 9.2 强制限制

- 沙箱无网络、非 root、只读根文件系统、禁提权、无额外 capabilities，不挂载 Docker socket 或业务目录。
- 每个任务独立临时目录与授权数据；输出只接受有大小限制的 JSON 和已验证附件，不解释输出为命令。
- 建议默认单次执行 30 秒、1 CPU、512 MiB 内存、64 PID、64 MiB 临时空间、10,000 行结果和 2 MiB JSON；分析最多并行 3 个假设，全局最多 4 个沙箱。管理员可在允许范围内调整。
- 宿主看门狗负责超时、取消及清理，租约失效后删除孤儿容器；资源限制实际探针不通过则拒绝动态执行。
- 生产 runner 位于专用 Linux 节点或 VM，不与业务数据库共享宿主权限；controller 管理容器运行时，但其身份不传给沙箱。API 不直接持有 Docker 管理权限。

Docker 官方说明了 daemon 管理接口的权限风险，本设计因此将其限制在专用 controller；参考 [Docker Engine security](https://docs.docker.com/engine/security/)。gVisor 与 Docker 的结合方式以 [官方运行指南](https://gvisor.dev/docs/user_guide/quick_start/docker/) 为依据，部署前仍须验证统计库兼容性和各项资源限制。

### 9.3 开发与失效模式

未检测到可用的合格 runner 时，动态代码功能返回 `SANDBOX_UNAVAILABLE`。开发可以测试已审核的纯函数及规则工具，但界面明确显示模式，动态沙箱验收保持未完成。禁止把 Docker 引擎未运行时的普通 Python 子进程自动当作后备沙箱。

沙箱拒绝、超时或基础设施异常均产生独立证据状态；其他独立假设继续运行，整个任务可部分完成。

## 10 任务、上下文和事件流

### 10.1 持久化队列

API 在同一数据库事务中保存范围版本、run 和 job，然后返回 202、run ID 与事件地址。任务幂等键包含用户、会话、客户端请求 ID；相同键且不同请求内容返回冲突。

worker 使用行锁领取 job，写入带递增 generation 的租约，默认心跳 10 秒、租约 60 秒。工作可重复执行，但步骤结果凭 `(run_id, step_key, input_hash)` 唯一提交；只有当前 generation 可以提交，取消后的迟到结果不更新当前看板。

每个会话用数据库唯一约束限制一个活动写任务；新的追问返回明确的运行中状态。并行子假设独立保存尝试记录，网络类临时失败最多重试 2 次；权限、输入和安全拒绝不自动重试。

scheduler 使用同一租约机制，订阅周期的唯一键为 `(subscription_id, period_start, period_end, config_version)`。轮询丢失通知不影响任务持久性，数据库为唯一状态来源。

### 10.2 SSE 与恢复

事件包含 run ID、单调 event ID、阶段、状态、时间和可显示的结果摘要。与步骤结果同事务落库；SSE 仅转发已提交事件，支持 `Last-Event-ID` 续传。客户端若游标已过保留期，读取完整快照后继续订阅。

SSE 每 15 秒心跳，网络中断不创建新任务。前端按 run/event ID 去重，切换会话取消旧订阅；权限撤销停止事件发送并清理活动缓存。

### 10.3 上下文修改规则

结构化范围包含指标、业务线、基期/现期、比较方式、维度筛选、分组、数据版本、目标版本（目标差时）和父范围版本。新维度默认追加，同维度明确修改时替换；“返回全国”只清除区域，“返回上一级”恢复父范围快照。

切换业务线创建新会话；切换指标提示并清除不兼容筛选。模型只提交范围补丁，服务器校验权限、字段兼容性与歧义后生成新版本。任何结果均关联范围摘要，不能只靠聊天文本恢复上下文。

后端维护 endpoint、model、超时、最大输入/输出、费用或用量上限和密钥引用。管理员配置的地址接受允许列表与 SSRF 校验；不允许普通用户覆盖。日志只记录脱敏摘要和用量。

规划器输出经过 schema 验证；执行器只接受工具允许列表和固定数据标识。模型无直接数据库连接，不接受用户文本中的权限提升请求。默认每阶段一次生成、一次格式修复；超时或预算耗尽明确中止或进入标识清楚的规则模式。

离线规则模式与在线模型模式共享同一数值引擎和证据结构，报告标记实际模式。在线适配器验收必须使用用户配置的可用服务；目前没有凭据，不能提前声称自然语言泛化已验证。

### 11.2 仿真分层

确定性模式直接调整因子，调用指标表达式，保存基期参数、调整值、约束和结果；两项 PRD 固定数值必须精确复算。前端只做即时预览，保存、报告和收益以服务端复算为准。

历史估计模式至少实现一个渠道预算/投入变化对流量或订单的响应案例：固定模拟生成机制，使用最早 70% 时间数据拟合，后 30% 做时间验证。估计记录输入、转换、系数、样本、误差和适用范围，不把相关回归系数自动称为因果弹性。

对有时间依赖的残差使用按连续日期块重采样，默认 7 天块、1,000 次抽样、固定随机种子，结合参数变化生成 95% 条件性预测区间；样本和验证不满足要求时不展示区间，说明缺失依据。模型完整验收必须至少有一个满足条件的历史场景。

超出训练数据范围的干预量标记外推，不生成保证收益。行动收益按联合情景计算，避免同一恢复空间多次相加。

## 12 API 和前端合同

API 前缀为 `/api/v1`，通过 OpenAPI 生成前端类型。统一错误包含 code、message、request_id 和结构化 details，禁止输出堆栈或秘密。金额作为十进制字符串传输；比例为明确约定的小数，展示时转换百分比/百分点。

| 资源族 | 主要操作 | 关键规则 |
| --- | --- | --- |
| auth / me | 登录、退出、当前用户及权限 | Cookie 会话、CSRF、权限修订 |
| datasets / imports | 上传、校验、发布、版本查询 | 异步导入；版本不可变 |
| metrics / metric-versions | 草稿、校验、发布、树查询 | 乐观锁；禁止循环和任意表达式 |
| dashboard | 指标、趋势、异常 | 必须指定或返回实际范围 |
| sessions / scopes | 新建、历史、范围补丁 | 所有权检查；业务线切换新建 |
| runs / events | 发起、状态、SSE、取消、重试 | 幂等键、租约、可恢复快照 |
| evidence / drilldowns | 证据、代码、透视表 | 输入快照绑定；分页及行数上限 |
| business-events / history | 事件维护、候选匹配、历史引用 | 当前授权及版本引用 |
| simulations | 参数校验、试算、保存、比较 | 服务端权威结果；输入范围校验 |
| reports / comments / exports | 草稿、批注、发布、归档、文件 | ETag/版本冲突返回 409；下载重验权 |
| subscriptions | 频率、范围、启停、执行记录 | 时区固定展示；周期去重 |
| admin / audit | 用户授权、配置、配额、日志 | 管理能力不等于数据访问权 |

列表统一游标或分页合同，最大页大小固定，排序字段允许列表化。错误码至少包含 FORBIDDEN、SCOPE_AMBIGUOUS、DATA_INCOMPLETE、VERSION_CONFLICT、RUN_BUSY、SANDBOX_UNAVAILABLE、EXECUTION_LIMIT、MODEL_UNAVAILABLE。

前端分别管理服务端数据、当前会话选择和短期表单输入；不在浏览器推算权限或凭空补足任务结果。相同分析版本的图表、透视表、证据和报告入口一起切换。

## 14 运维、发布与质量流程

### 14.1 环境与部署

开发、测试、部署配置分开；禁止把演示账号和默认密钥带入生产模式。Compose 管理 API、worker、scheduler、PostgreSQL、前端代理及集成测试服务；按用户要求在选定的远程环境部署运行，不在本机新建运行环境。生产 runner 使用专用节点接口。数据库和控制端口不直接暴露公网。

用户已确认现有 Docker 位于本机，不能据此认定已有远程环境。计划选用远程 Linux CPU 服务器承载业务、数据库和统计分析，另按沙箱隔离要求落实 runner。DeepSeek 模型通过远程 API 调用，不在本机或业务服务器部署模型权重，因此当前方案不需要 GPU 或模型显存。调用方式依据 [DeepSeek 官方接入文档](https://api-docs.deepseek.com/)。

Docker 镜像、构建缓存、依赖、数据库和报告附件会占用运行机器的磁盘，资源规划须单独核算，参见 [Docker Desktop 资源配置说明](https://docs.docker.com/desktop/settings-and-maintenance/settings/)。本项目将这些新增运行开销安排在远程环境，避免扩大本机 Docker 存储。

依赖使用锁文件，镜像固定摘要，迁移脚本入库；生产模式拒绝不安全默认凭据。变更遵循兼容的 expand/contract 迁移，破坏性变更不与业务代码首次切换同一步执行。

### 14.2 发布与恢复

每次发布记录源提交、依赖锁、镜像、迁移版本、数据夹具版本和测试结果。先执行预发布冒烟与数据库备份，再滚动或维护窗口切换，失败恢复上一镜像；数据库回滚依据可逆迁移或备份恢复，不承诺任意 down migration 无损。

首版提供备份和恢复演练：数据库与报告附件版本一致，恢复后检查账号、数据版本、已发布报告及队列状态。RPO/RTO 和保留期在实际部署前确定；本项目交付演练脚本与结果，不虚报生产 SLA。

日志使用 request/run/step ID 关联，记录延迟、失败率、队列等待、沙箱拒绝/超时、模型用量和导出耗时。日志脱敏，审计只追加；磁盘配额、过期临时文件和孤儿任务有清理机制。

### 14.3 测试层次

| 层次 | 必须验证的内容 |
| --- | --- |
| 算法单元及性质测试 | PRD 固定数值、加法/LMDI/Shapley 守恒、超过 8 个交叉切片的比率分摊、零值/负值/抵消、比率单位、非法分母 |

仓库当前无远端，先交付可本地运行的 CI 命令及工作流文件；远端创建、发布和部署在目标明确后实施，不伪造 PR 或流水线链接。
