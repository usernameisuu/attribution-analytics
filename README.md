# 经营归因分析系统

面向课程验收和简历展示的经营归因分析项目，目标是实现接近真实开发的分析工作台。当前需求、模块和待决事项见 [项目 SPEC](经营归因分析系统-SPEC.md)。

## 当前状态

项目从原目录迁移而来，保留了 Git 历史及原有未提交修改。已有 FastAPI 后端、React + TypeScript 前端、PostgreSQL 数据模型及部分归因、会话、事件和权限相关代码。现有实现尚未依据最新 SPEC 完成全面复核，不能视为所有需求均已实现；后续应先评估并决定复用或重构范围。

后端健康检查中的能力标记显示，沙箱和统计检验目前尚未实现。两场景完整闭环、多格式导出及其他交付要求也需逐项验证，实际运行状态以测试结果为准。

## 约定方向

- 先本地运行，再考虑云服务器部署；现有 PostgreSQL 服务位于虚拟机 Docker 中，复用前应确认连接与权限。
- 使用模拟数据先跑通电商 GMV 和快消品利润率两个场景，再验证外部数据库接入。
- 大模型服务选用 DeepSeek；密钥通过安全配置提供，不提交到版本库。付费调用前须确认费用与预算。
- 分析沙箱拟使用虚拟机上的 Docker，隔离方案和 Windows 到虚拟机的调度方式尚待设计验证。

## 目录

- `backend/`：Python 后端、迁移、测试与分析模块。
- `frontend/`：React 前端与构建配置。
- `经营归因分析系统-SPEC.md`：需求、模块、开发步骤与待评审事项。

迁移后的虚拟环境可能仍引用原路径，运行前需要检查并按新路径重建或重新安装依赖。数据库、运行命令、迁移状态及现有集成测试需核验后再写入操作说明；不要对共享 PostgreSQL 服务或已有数据执行清理操作。
