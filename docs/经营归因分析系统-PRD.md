## 2 产品背景与目标

### 2.1 背景与问题

经营指标出现异常后，分析人员需要在报表、数据查询和业务记录之间反复核对：先确认变化发生在哪些指标和维度，再检验可能原因，最后评估可以采取的行动。仅显示涨跌幅无法回答“为什么变化、各因素影响多大、采取行动后可能改善多少”。

本系统面向企业核心经营分析场景，把指标拆解、多维下钻、假设验证、业务事件关联和策略推演整合到同一工作台，形成可追溯、可复算的经营分析报告。

### 2.2 产品目标

| 编号 | 目标 | 成功判定 |
| --- | --- | --- |
| G01 | 解释指标异常的量化来源 | 各驱动因子贡献量与整体变动守恒，能定位主要异常维度 |
| G02 | 用数据验证假设 | 每个已验证假设有实际执行记录、数据依据及结论状态 |
| G03 | 支持持续探索 | 多轮追问继承分析对象、时间与筛选范围，结果随探查更新 |
| G04 | 结合业务语境 | 关联符合时间及业务范围的事件，明确证据强弱与结论边界 |
| G05 | 支持业务决策 | 提供可解释的情景模拟及包含负责人、周期、量化收益的行动项 |
| G06 | 完成可运行交付 | 至少两个业务场景完成从发现异常到三种格式报告导出的全过程 |

### 2.3 范围边界与不可接受结果

原文要求可运行前端、后端、统计检验与代码沙箱、示例数据、完整演示及报告导出。示例数据可以是可复现的业务模拟数据，分析结果必须由实际计算产生。

以下作为建议边界：首版提供经营分析与行动建议；调整价格、修改预算、执行营销等真实业务动作由使用者在业务系统完成。任意数据库连接器、企业统一身份集成、外部消息渠道及生产高可用要求须结合使用环境确认，不作为已确定的交付承诺。

以下结果不能通过验收：

- 图表、贡献量、统计结论或第二场景仅使用预先写好的展示内容，修改数据后不重新计算。
- 未执行查询或检验，却把假设标为已验证；把模型措辞当作统计证据。
- 仅因事件时间接近便断言因果；把模拟收益展示为实际收益或承诺。
- 会话切换后串用数据，刷新后丢失已完成步骤，或对无权限数据继续分析和导出。
- 导出按钮存在但文件无效、内容缺项，或报告与同一版本的分析结果不一致。

## 3 产品方案与交付范围

### 3.1 可选方案

| 方案 | 具体方式 | 收益与限制 | 评估 |
| --- | --- | --- | --- |
| 规则与统计驱动 | 根据指标和维度生成预设假设，通过真实查询、检验和模板形成结论 | 容易复现，但自然语言泛化有限，单独使用不能覆盖原文的大语言模型要求 | 可作演示回退能力 |
| 大模型规划与受控计算结合 | 模型理解问题、提出假设与解释；数值由指标引擎及受控 SQL/Python 执行产生 | 满足多轮探索和可追溯计算，需要明确工具边界及失败处理 | 推荐的完整交付方案，待用户确认 |
| 大模型自由执行分析脚本 | 模型直接组织查询和任意脚本执行 | 灵活，但权限、资源与结果一致性难以控制 | 不建议作为首版默认方案 |

本文按第二种方案描述产品能力，同时允许第一种作为明确标识的回退模式。此为编写者建议，尚未完成技术方案选定；具体框架、数据库与隔离实现留待技术设计。

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| M1 核心分析闭环 | 登录与权限、示例数据、指标模型、大盘、三栏工作台、真实分解与检验、多轮下钻、事件关联、模拟、三格式导出 | 一个场景贯通，核心数值及安全边界验证通过 |
| M2 完整实战交付 | 第二场景、指标及数据源管理、全部要求图表、报告批注与版本、简报订阅、恢复机制、审计、完整演示与截图 | 本文 P0 和 P1 全部完成，原文八项验收标准逐项通过 |

### 3.3 场景建议

建议首批采用“电商 GMV 下滑”和“快消品利润率异动”：分别覆盖乘法因子分解、加法利润分解及比率指标分析。SaaS 续约率保留为可替换场景；原文要求至少两个场景，并未要求三个全部实现。

## 6 核心业务流程与状态

### 6.1 从异常发现到报告

1. 用户在大盘选择异常指标，或输入自然语言分析需求。
2. 系统识别目标指标、业务线、分析期、基期及筛选条件；缺少关键字段或存在多个解释时先澄清。
3. 校验权限、数据覆盖和指标定义，记录本次分析的数据与指标版本。
4. 读取指标树，完成整体变化和第一层贡献分解。
5. 生成 3～5 个不同且可验证的假设；数据不足时说明缺少的条件，不补造假设证据。
6. 生成受控 SQL/Python 探查，在配额允许时并行执行相互独立的假设验证，完成维度分析与统计检验，展示实际进度。
7. 检索异动窗口前后 3 日的事件及授权历史归因案例，结合渠道、区域、品类等范围形成解释与证据链。
8. 用户继续追问，系统继承已有范围并产生新的分析版本；右侧看板随结果更新。
9. 用户调整可干预因素，保存模拟情景并查看行动建议。
10. 生成报告草稿，经分析师审核发布，支持批注、归档及三种格式导出。

### 6.2 会话与任务状态

会话是持续探索的容器，一个会话包含多个独立任务和分析版本。建议任务状态为：待澄清、排队中、运行中、部分完成、已完成、失败、已取消。

| 触发条件 | 状态与处理 |
| --- | --- |
| 目标指标或时间口径不明确 | 待澄清；保留用户已提供的有效条件 |
| 参数与权限校验完成 | 排队中或运行中；生成唯一任务标识 |
| 某个假设失败而其他步骤成功 | 部分完成；保留成功结果及失败原因，不自动标记全量成功 |
| 全部必需步骤成功 | 已完成；保存结果版本和可恢复快照 |
| 关键数据无法访问或核心计算失败 | 失败；给出重试或修改条件入口 |
| 用户取消 | 停止尚未完成的任务，终止受控执行；保留取消前已完成的结果 |
| 刷新、短暂断网或切换会话 | 恢复服务器状态和最近快照；已完成步骤不因重新连接重复执行 |
| 条件、指标版本或数据版本变化 | 创建新分析版本；旧结果保留并标明原范围，不冒充最新结果 |

一个会话建议同一时刻只有一个修改分析状态的任务；重复点击返回同一任务，新的追问在上一任务完成或取消后执行。不同会话的范围、结果和执行事件必须隔离。

## 7 功能需求

### FR01 登录与基础授权 P0

- 提供统一登录入口、退出及会话失效提示；账号绑定角色和业务数据范围。
- 未登录不能访问业务数据；无权限操作返回明确提示，前端隐藏入口不能替代后端校验。
- 数据权限撤销后，阻止后续查询、恢复、下载和后台订阅访问，并使前端缓存失效。
- 建议示例环境提供三类演示账号及授权差异说明；真实企业身份集成方式待确认。

**验收：** 三类账号执行授权及未授权操作，服务端结果与第 4 节一致；退出后旧登录态不能继续访问。

### FR02 业务线、指标域与数据源 P0 核心 P1 管理

- 支持多业务线与指标域，并在大盘、指标字典、会话和报告中显示归属。
- 数据源配置包含名称、类型、授权范围、同步状态、数据覆盖期和最近成功时间；凭据不返回普通页面或报告。
- 支持示例数据集导入、连接测试、字段映射、数据校验和失败明细；真实连接器类型待确认。
- 校验重复业务键、必要字段缺失、数值越界、日期缺口和单位不一致；错误批次不能覆盖可用数据。
- 每次分析绑定可追溯的数据版本或快照标识，记录查询时间和数据截止时间。

**验收：** 导入有效数据后可查询分析；非法数据说明具体错误；切换业务线后指标、数据和历史内容不会串用。

### FR03 指标字典与公式管理 P0 核心 P1 管理

- 支持原子、派生和复合指标，维护编码、名称、说明、单位、聚合口径、数据来源、业务域和负责人。
- 复合指标配置加法、乘法或比率公式及多层拆解关系，支持杜邦式层级分析。
- 快消品场景至少提供毛利率和净利率及其分子、分母定义，支持从比率下钻到营收、成本和利润。
- 区分可加总数量、金额与不可直接相加的比例指标；比例按分子分母重新聚合。
- 保存前校验未知引用、循环依赖、单位冲突、除零和不支持的表达式；公式不能当作任意代码执行。
- 建议全局指标采用草稿与已发布版本。新会话使用当前已发布版本，历史会话保留原版本。

**验收：** 新建有效复合指标后能够拆解；循环引用或非法公式被拒绝；更新全局指标不悄悄改写历史报告。

### FR04 指标异动大盘 P0

- 展示基期值、现期值、变化额、变化率、数据更新时间及趋势。
- 支持业务线、指标域、时间和主要业务维度筛选；比较方式覆盖环比、同比和目标差。
- 按可配置的异常阈值标识指标，展示阈值及触发原因；目标差只有配置了目标数据时可用。
- 一键发起归因，将指标、时间、比较方式和当前筛选条件传入新会话。
- 数据未更新、空结果、无比较数据时显示对应状态，不以零值代替缺失值。

**验收：** 同一范围下大盘与工作台的基期、现期和变化额一致；从异常卡发起后无需重新输入已有条件。

### FR05 三栏工作台与会话管理 P0

- 新建、重命名和切换会话，浏览历史问题、分析步骤、中间结果和报告关联。
- 左侧导航保持当前目标指标；中间区承载多轮交互；右侧呈现当前分析版本。
- 流式展示已受理、查询中、检验中、已完成、失败等真实执行事件，不使用固定动画伪装工具执行。
- 支持取消、失败步骤重试、刷新恢复和中间快照持久化；重复请求不重复创建报告或任务。
- 每个分析结果显示范围摘要，至少包含指标、分析期、基期、维度筛选及数据版本。

**验收：** 分析期间刷新和切换会话后可恢复正确状态；重试不重复生成同一结果；失败步骤能够单独识别。

### FR06 意图识别与多轮下钻 P0

- 识别指标、比较时间和渠道、区域、品类、客群等筛选与分组意图。
- 对“继续看华东”“其中付费渠道呢”等追问继承上一有效分析范围，新增条件或替换条件需在范围摘要中体现。
- 明确切换指标、时间或业务线时更新对应范围；存在多个合理解释时先澄清，不擅自选择。
- 支持清除筛选、返回上一级和回看历史版本；继承与清除的条件对用户可见。
- 事实性结论引用结果表、指标计算、执行记录或业务事件；超出数据范围的问题说明可回答边界。

**验收：** 连续完成“分析 GMV → 看华东 → 看其中付费渠道 → 返回全国”的追问，查询范围、数值和右侧证据同步变化。

### FR07 指标分解与可视化 P0 核心 P1 完整图表

- 加法模型使用差额分解；乘法模型按原文采用 LMDI；维度贡献采用 Shapley 或占比贡献法并显示所用方法。
- 多级指标树可展开，显示节点基期、现期、变动及对子层的拆解；同层节点贡献与对应父节点变化一致。
- 瀑布图显示基期、各因素贡献、现期及总差额；不把不同层级或不同维度的贡献混加。
- 透视表支持多维交叉、层级折叠、列头排序、差额高亮和当前表格导出；导出包含当前筛选及汇总口径。
- 提供下钻时序趋势图和桑基图；桑基图须明确流量定义，不能将带正负号的贡献强行作为非负流量绘制。

**验收：** 至少两个场景使用独立指标模型，图表与底层结果相符；修改数据后重新分析，贡献值随之变化并继续守恒。

### FR08 假设生成与统计验证 P0

- 结合指标因子变化和维度特征生成 3～5 条候选假设，每条说明待检验判断、范围和所需数据。
- 每条假设生成可执行的数据探查代码，经过权限与安全检查后执行；展示代码、执行时间、结果摘要和证据引用。
- 相互独立的假设在沙箱配额内并行验证，存在前置数据依赖的步骤按依赖顺序执行；每条验证单独显示状态并按假设标识归集结果，一条失败不取消其他独立验证。
- 根据数据类型选择适合的相关性、比例、均值或分层比较方法，并记录样本量、效应量、检验参数及适用条件。
- 通过分层、对照、时间趋势等适用手段检查混杂解释；证据不足时限制结论强度。
- 假设状态包括待验证、验证中、获得支持、已排除、证据不足和验证失败。低于既定证据阈值的已完成检验按原文标为已排除，并解释为“未达到支持标准”；数据缺失、低检验效力或执行失败不能伪装成反证。
- 统计显著性、贡献大小和业务价值分别呈现；原文“置信度”需明确计算定义，不能用模型自评或简单的 1−p 代替假设成立概率。

**验收：** 一组受支持和一组被排除的假设均有真实运行结果；构造混杂或样本不足案例时，系统不输出无条件的因果判断。

### FR09 受控 SQL 和 Python 执行 P0

- 提供只读查询及脚本分析执行能力；执行对象只能访问本任务授权的数据切片。
- 禁止数据库写入、越权查询、未经允许的网络和文件访问、任意外部命令以及模型或数据库凭据读取。
- 配置运行时长、内存、CPU、结果行数和输出体积上限，超限终止并展示具体原因。
- 同时限制单任务和总并发配额，隔离各假设执行上下文；取消任务时停止其全部未完成子任务，不影响其他会话。
- 保存代码内容或可核对引用、输入版本、参数、执行状态、耗时和结果摘要，供证据追溯。
- 代码生成与代码执行分离；语法校验、白名单和只读账号不能替代执行隔离。具体隔离方案需在技术设计中明确并通过越界测试。
- 无法提供满足边界的隔离时，动态脚本执行功能标记为不可用；预定义分析工具可作为明确标识的回退，不能据此宣称动态沙箱已验收。

**验收：** 写入、越权读取、外联、系统命令和资源耗尽测试均被阻断或受控终止；合法只读分析仍能完成。

### FR10 业务事件日历与证据链 P0

- 管理事件标题、类别、起止时间、业务线、渠道、区域、品类、描述、来源、预期影响及维护人。
- 支持营销大促、运营调整、系统故障、竞品动作、政策变化和宏观事件，按时间线与指标域筛选。
- 对分析窗口前后各延伸 3 日检索候选事件；再按业务维度及影响方向判断是否相关，展示匹配理由。
- 将事件与已验证数值证据、假设和结论关联，区分“时间重合”“统计关联”和“有对照支持的解释”。
- 按业务线、指标、异常类型与维度检索授权范围内的历史归因库，引用历史报告版本并展示与当前时间、数据和业务范围的差异；历史结论用于生成候选解释，本次判断仍需当前数据验证。
- 没有事件时保留纯数据归因；存在多个事件时展示竞争解释，允许分析师补充证据及审核意见。

**验收：** 窗口内且业务范围相关的事件进入候选链；仅时间接近但业务范围无关的事件不能自动成为首要原因；可检索相关历史案例并追溯来源，不能越权引用或直接沿用旧结论。

### FR11 What-If 仿真与行动建议 P0

- 从分析结果选择可干预因素，提供带单位、范围与步长的滑块或输入框，显示相对变化和绝对变化。
- 依据指标公式、可解释的弹性系数或历史估计重新计算，提供敏感度曲线与多个命名情景对比。
- 每个情景记录原始值、调整值、其他条件假设、估计方法和模型或数据版本。
- 展示预计改善值、方向和适用周期；区间须有可说明的历史估计或抽样依据，没有依据时只给条件性点估计。
- 完整交付至少一个演示必须利用历史数据估计驱动因子弹性或敏感性，并结合历史波动率生成有依据的收益区间；记录历史窗口、样本量、估计方法、区间含义及验证结果，不能用固定上下浮动比例代替估计。
- 生成绑定量化驱动因子的行动项，包含责任岗位、具体动作、优先级、预计恢复周期、预期挽回金额及依赖条件。
- 多个行动作用于同一驱动因子时，联合模拟后计算总收益，不能简单加总造成重复计量。

**验收：** 参数变化后模拟结果按同一公式更新，保存和恢复数值一致；至少一个情景提供可复算的历史弹性或敏感性估计及收益区间；不合法参数被阻止；行动项能够追溯到驱动因子和模拟情景。

### FR12 报告生成与三格式导出 P0

- 按第 11 节七部分组装完整报告，保存分析范围、数据版本、生成时间、作者和结论限制。
- 支持在线预览、打印、Markdown、PDF 和 Excel 导出；报告与导出使用同一分析快照。
- Markdown 包含可独立理解的文本、数据表和必要图表引用；PDF 的中文、图表、分页和表头清晰；Excel 保留数值单元格、单位、证据索引与模拟结果。
- 导出当前透视表时与整篇报告导出区分，保留筛选条件和汇总口径。
- 导出失败时说明原因并允许重试，不返回损坏文件或伪装成功；导出接口重新检查授权。

**验收：** 三种文件实际生成并可打开；基期、现期、贡献量、证据和模拟数据与同版本页面一致；文件不包含密钥及越权明细。

### FR13 报告协作与归档 P1

- 分析师可编辑报告说明、结论表述和行动项；计算产生的数值从分析版本引用，不能直接改文案伪造统计事实。
- 支持授权用户对报告段落批注、回复和处理批注；保留操作人和时间。
- 建议采用“草稿 → 已发布 → 已归档”的生命周期；修改已发布报告生成新草稿版本，旧版本可追溯。
- 保存时校验版本，并发修改冲突需提示重新加载或合并，不能无提示覆盖他人内容。
- 首版建议使用共享访问、批注和版本控制满足协作；是否需要多人同时编辑正文列为待确认项。

**验收：** 两名授权用户可完成批注协作；过期版本保存被识别；发布后可查询作者、版本与关联分析快照。

### FR14 周期性归因简报订阅 P1

- 用户配置业务线、指标范围、频率、触发时间和异常条件，支持启停与取消。
- 建议默认提供每日、每周和指定时刻，使用明确的时区，并在界面展示下一次执行时间。
- 系统按订阅范围生成简报；没有异常时输出无异常状态，不编造归因内容。
- 建议首版在系统报告中心交付结果及未读提示。邮件、短信或企业聊天渠道仅在明确接入后启用。
- 建议将自动简报与正式发布报告区分：成功生成后，授权订阅者可查看标注“系统自动生成，未经人工复核”的简报；其状态为“已生成”，不等于正式报告的“已发布”。需要正式发布时转为报告草稿，由分析师审核。此审核方式列入第 16 节待确认。
- 同一订阅周期避免重复生成；失败记录原因及重试状态；权限失效后停止受限数据处理。

**验收：** 在受控测试时钟或测试周期内生成一次简报，授权订阅者可查看并辨认人工复核状态；关闭后不再触发；跨业务线权限及重复触发检查通过。

### FR15 审计与运行管理 P0 核心 P1 管理界面

- 审计登录、数据接入、指标和事件修改、会话任务、代码执行、模拟、报告发布导出、订阅及权限变更。
- 记录操作者、业务对象、动作、时间、任务关联、结果和失败原因；分析输入中的敏感内容按授权处理。
- 管理员查看模型调用状态、耗时、错误、用量和沙箱资源情况，配置模型参数与执行配额。
- 密钥只供受控后端使用，配置页面和日志采用脱敏展示；日志保留周期待部署环境确认。

**验收：** 从一份报告可追溯到会话、数据和指标版本、代码执行及发布导出记录；日志不泄漏凭据。

## 8 指标与分析业务规则

### 8.1 时间与聚合口径

| 规则 | 要求 |
| --- | --- |
| 时间区间 | 页面显示起止日期和时区；内部边界规则保持一致。建议按 Asia/Shanghai 自然日展示，技术实现采用明确的半开时间区间 |
| 环比与同比 | 展示实际比较的日期范围及天数；同比节假日、闰日和大促错位策略须在分析配置中说明 |
| 数据完整性 | 当前周期未结束或基期缺数时醒目标记；不将部分天数与完整周期无提示比较 |
| 目标差 | 记录目标值、目标版本及适用周期；没有目标数据时禁止生成目标差分析 |
| 比例聚合 | 转化率、利润率等按聚合后的分子与分母计算，不能直接平均分组比例 |
| 业务单位 | 金额明确币种、税费、退款和确认时间口径；不同单位或币种不能直接合并 |

### 8.2 变化与贡献

- 总变化量 = 现期值 − 基期值；常规变化率 = 总变化量 ÷ 基期值。基期为零时变化率显示“不适用”；负基期同时展示绝对变化并解释百分比口径。
- 加法模型按每项在公式中的符号计算贡献。例如利润 = 营收 − 成本，成本上涨对利润是负向贡献。
- 正值乘法模型采用 LMDI 分解。零值、负值和缺失值不得静默替换为小正数；建议不适用时使用明示的替代分解或提示不可分解，具体算法在技术设计中确定。
- 贡献率 = 单项贡献量 ÷ 总变化量。允许负值和大于 100% 的值；它表示相互抵消后的占比，不是概率。
- 总变化为零或接近数值容差时保留贡献量，贡献率显示“不适用”，说明存在抵消效应。
- 比率指标的变化使用百分点。利润额分解不能直接代替利润率分解；利润率需按分子、分母的实际函数另行计算。
- 同一层级、同一口径的贡献量必须守恒；因子拆解和渠道、区域等不同维度的拆解是不同视角，不能彼此相加。
- 金额计算保留内部精度，最终按币种精度展示。建议货币贡献和与总变化的展示误差不超过 0.01 元；其他量纲按公开的数值容差验收，禁止用未解释的残差填平算法错误。

### 8.3 假设与证据口径

建议统计检验默认显著性水平为 0.05，但需按检验方式、样本和多重比较策略明确适用条件，参数随分析版本保存。证据卡至少显示方法、样本量、效应方向、效应量、适用的 p 值或区间及限制。

“已排除”表示按本次数据及既定规则未达到支持标准，不等于证明该原因永久不存在。样本不足、假设不满足或代码失败使用独立状态。高贡献不自动代表显著，高显著也不自动代表高业务价值。

业务事件首先是候选解释。只有存在适当对照或其他可支持因果识别的证据时，才提升结论强度；在报告中保留识别假设和限制。系统不保证所有分析都得到唯一根因。

### 8.4 模型调用与降级

- 大模型用于意图理解、候选假设、查询计划及有证据的解释；金额、比例和检验结果来自实际计算。
- 模型输出结构不合法时允许有限重试；仍失败则显示失败或进入明确标识的规则回退模式。
- 模型不可用时，已完成的数值分析仍可查看、复算和导出；未完成的语义分析不得标为成功。
- 无模型凭据的演示环境可使用规则模式运行，但完整模型能力须在有效模型配置下另行验收。
- 业务数据、用户文本和外部事件描述不能覆盖系统的权限和工具执行边界。

### 9.2 场景数据集

| 场景 | 数据表或等价数据对象 | 核心维度与一致性要求 |
| --- | --- | --- |

### 9.3 建议测试数据规模

为便于实战复现，建议每个场景覆盖至少 90 天、4 个渠道、3 个区域、4 个品类和 2 类客群；示例全组合日聚合数据约 8,640 行/场景。原子明细建议每场景至少 10,000 行。不是每类业务都必须强行套用相同维度，最终数据字典需明确实际适用项。

常规趋势数据与第 10 节的固定数值验收夹具分开管理。另提供零基期、负利润、缺数据、重复键、无事件、样本不足、模型失败和沙箱超限的异常数据或可重复触发方式。

至少一个场景的历史数据须包含可用于估计驱动因子响应及波动的观测变化，保存模拟生成机制，并划分拟合和验证数据或使用明确的时间回测规则，以支持仿真收益区间的实际估计及验证。

| 成交订单数 | 5,000 | 3,600 |
| 客单价 | 200 元 | 180 元 |
| GMV | 1,000,000 元 | 648,000 元 |

夹具口径限定每位成交访客一笔有效订单，因此 GMV = 访客数 × 转化率 × 客单价。真实数据允许多笔订单时，必须补充人均订单数因子，或将转化因子明确定义为订单数/访客数，不能混用购买人数转化率。

预期结果：GMV 下降 352,000 元，降幅 35.2%；流量增加为正向贡献，转化率和客单价下降为负向贡献，LMDI 贡献量总和为 −352,000 元。

建议模拟“促销引入低转化流量”和“特定渠道结算故障”，同时放入一个不相关事件。演示从整体分析下钻到区域、渠道和品类，排除至少一个有数据可检验的候选假设。

What-If 固定检查：其他条件不变，转化率由 3% 提高到 3.5%，预计 GMV 为 756,000 元，比现期增加 108,000 元；显示为条件性模拟收益。

### 10.2 快消品利润率异动

| 指标 | 基期 | 现期 |
| --- | --- | --- |
| 营收 | 1,000,000 元 | 950,000 元 |
| 原材料成本 | 500,000 元 | 540,000 元 |
| 物流履约成本 | 100,000 元 | 110,000 元 |
| 渠道佣金 | 50,000 元 | 57,000 元 |
| 其他经营成本 | 100,000 元 | 100,000 元 |
| 财务费用与所得税费用 | 0 元 | 0 元 |
| 毛利润 | 500,000 元 | 410,000 元 |
| 毛利率 | 50% | 约 43.1579% |
| 经营利润 | 250,000 元 | 143,000 元 |
| 示例净利润 | 250,000 元 | 143,000 元 |
| 示例净利率 | 25% | 约 15.0526% |

该简化夹具定义毛利润 = 营收 − 原材料成本，物流、佣金和其他经营成本作为期间费用；净利润 = 经营利润 − 财务费用 − 所得税费用，后两项在本夹具中明确为零，因此经营利润与净利润数值相同。实际数据须按企业批准的指标及成本归集口径配置，不能把本夹具的简化定义直接套用为法定报表口径。

净利润变化为 −107,000 元：营收贡献 −50,000 元、原材料贡献 −40,000 元、物流贡献 −10,000 元、佣金贡献 −7,000 元、其他成本和财务税费贡献 0 元。毛利率下降约 6.8421 个百分点，净利率下降约 9.9474 个百分点；两种比率的分解应分别计算，不能直接复用利润额贡献百分比。

建议模拟“原材料价格上涨”和“履约成本变化”，关联对应业务事件。演示多层利润树、成本下钻、统计验证、事件解释和报告导出。

What-If 固定检查：现期原材料成本降低 5%，其他条件不变，成本减少 27,000 元，净利润升至 170,000 元，净利率约 17.8947%，提高约 2.8421 个百分点；毛利润升至 437,000 元，毛利率为 46%。

## 11 报告内容与格式

| 部分 | 必须包含的内容 |
| --- | --- |
| 异动背景与问题定义 | 业务线、目标指标、周期、基期、现期、总差额和变化率、数据口径与截止时间 |
| 因子贡献率拆解 | 拆解方法、指标层级、因素贡献量和贡献率、方向、守恒校验、瀑布图与数据表 |
| 细分维度下钻证据 | 异常集中维度、当前筛选、透视表、趋势、主要变化及覆盖限制 |
| 核心归因结论 | 首要与次要因素、内外部诱因、贡献规模、结论强度和备选解释 |
| 因果证据链与检验置信度 | 假设状态、数据来源、代码执行引用、统计方法和结果、事件来源、因果识别限制 |
| What-If 情景模拟结论 | 情景参数、其他条件假设、预测变化、收益及有依据的区间、估计方法 |
| 可落地策略行动清单 | 量化驱动因子、动作、责任岗位、优先级、周期、预期收益和实施依赖 |

报告页头或元信息必须包含报告状态、版本、作者、生成时间和分析快照。正式报告发布需要分析师审核，部分完成的分析可生成带明显缺项说明的草稿，不能以完整报告状态发布。周期自动简报按 FR14 单独标记生成状态和未经人工复核状态，不能自动取得正式报告的发布状态。

Excel 建议包含“分析概览、因子贡献、下钻明细、假设证据、事件关联、情景模拟、行动清单”工作表；PDF 须避免中文乱码、图表裁切及表格跨页无表头；Markdown 中的图表资源若使用外置文件，须随导出一同提供，不能依赖开发机的绝对路径。

## 12 异常与边界处理

| 情况 | 用户可见行为 | 数据与任务处理 |
| --- | --- | --- |
| 问题缺少关键范围 | 提出针对性的澄清，保留已知条件 | 不在隐含范围上执行查询 |
| 空数据或基期缺失 | 说明覆盖不足及可用日期 | 不以零补齐，不输出虚假贡献 |
| 总变化为零或因素相互抵消 | 展示各项贡献量，贡献率不适用 | 保留真实正负项 |
| LMDI 输入不适用 | 标明原因及实际替代方法或不可分解状态 | 不静默修改输入 |
| 样本不足或检验假设不满足 | 标为证据不足 | 不把技术失败或低效力当作业务反证 |
| 模型超时或输出不合法 | 提示失败、重试或明确进入回退模式 | 保留已完成计算 |
| 查询或脚本超限 | 展示执行限制与可调整范围 | 终止超限任务并记录审计 |
| 同时存在多个事件 | 展示候选解释与区分依据 | 不强制选择唯一原因 |
| 分析中权限被撤销 | 停止受限操作并提示 | 清理前端缓存，阻止续查、导出及后台访问 |
| 数据或指标发生更新 | 显示当前结果所用版本及更新提示 | 重新分析生成新版本 |
| 断网、刷新或重复请求 | 恢复已受理任务状态 | 不重复执行已完成步骤 |
| 并发编辑报告 | 提示版本冲突 | 不直接覆盖他人修改 |
| 模拟参数越界 | 指明有效区间 | 不保存无效情景 |
| 报告导出失败 | 明确失败并提供重试 | 不返回不完整成功结果 |

## 13 非功能要求

以下性能数字为建议验收基线，须在指定机器和模型环境下确认，不作为已测量结果。建议基准采用 4 核 CPU、8 GB 内存、10 个并发活跃用户及第 9.3 节的数据规模，分别记录冷启动和稳定运行结果。

| 编号 | 领域 | 建议验收要求 |
| --- | --- | --- |
| N01 | 交互响应 | 稳定运行下大盘及会话加载 P95 ≤ 3 秒；分析请求受理反馈 P95 ≤ 1 秒 |
| N02 | 分析耗时 | 示例数据的规则/统计模式端到端 P95 ≤ 30 秒；模型模式单独记录耗时，建议 120 秒上限后明确反馈超时或部分完成 |
| N03 | 模拟响应 | 使用已加载数据的简单公式情景重算 P95 ≤ 300 毫秒；复杂服务端计算显示进行中状态 |
| N04 | 导出耗时 | 指定样例报告三格式分别测量，建议单次导出 ≤ 15 秒；超时有可见状态 |
| N05 | 一致性 | 同一数据、公式、参数及算法版本的数值结果可复算；模型措辞变化不改变计算事实 |
| N06 | 安全 | 服务端权限、数据范围隔离、只读查询和执行资源边界有效；无凭据泄漏 |
| N07 | 可恢复性 | 页面刷新和服务重启后已持久化会话、报告及完成步骤可恢复；中断任务显示真实状态 |
| N08 | 可用性 | 表单错误有字段级说明；图表提供对应数据；颜色不是区分正负和假设状态的唯一方式 |
| N09 | 兼容性 | 建议支持桌面 Chrome 和 Edge，验收时记录实际版本；1280 像素宽度可完整使用主要流程 |
| N10 | 可观测性 | 用户看到任务状态，管理员可关联查询任务、工具执行、模型耗时及失败日志 |

性能测试至少固定数据、机器、并发方式、请求样本数与模型配置；不能把少量手工点击结果当作 P95。生产容量、高可用、备份、审计保留及灾难恢复目标待实际使用环境确认。
